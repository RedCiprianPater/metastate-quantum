# --- Build toolchain (pinned to avoid pkg_resources removal in setuptools 70+) ---
# Newer setuptools (>=70) doesn't reliably expose pkg_resources inside pip's
# isolated build envs, which breaks the setup.py of older sdists such as
# ibm-platform-services 0.55.2 (line 19: `import pkg_resources`). Pinning
# here plus --no-build-isolation in render.yaml means any sdist that pip
# does end up building will use this setuptools and its pkg_resources.
setuptools>=65,<70
wheel

# --- Cross-cutting HTTP client pin (resolves the urllib3 collision) ---------
# Four packages in this tree touch urllib3 with mutually-exclusive constraints
# if we let each resolve independently:
#
#   qiskit-ibm-runtime 0.30.0  →  urllib3>=1.21.1               (lower bound only)
#   ibm-cloud-sdk-core 3.20.x  →  urllib3>=2.1.0,<3.0.0         (v2.1+ only)
#   oqtopus-client 1.1.x       →  urllib3>=1.25.3,<2.1.0        (v1 or v2.0.x)
#   quri-parts-oqtopus 1.1.3   →  urllib3                        (any)
#
# The 3.20.x sdk-core line collides hard with oqtopus-client. Pinning
# urllib3 to <2.0.0 forces pip to walk all the way back to ibm-cloud-sdk-core
# 3.16.7, which is the newest release still declaring urllib3<2.0.0 AND
# shipping a full py3-none-any wheel. That side-steps the sdist trap that
# was killing the build at ibm-platform-services 0.55.2 (sdist-only).
urllib3>=1.26.0,<2.0.0
